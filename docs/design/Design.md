# hima. — Design Specification

> **Version:** 0.2 (MVP)  
> **Platform:** Flutter / iOS・Android  
> **Last updated:** 2026-11-16  
> **Status:** デザイン方針。実装前に細部を調整してよい。

## 0. 2026-11-16 の決定事項

初版のあとに決まった内容です。初版と食い違う場合はこちらを優先します。

- プロダクト名は **`hima.`**（ロゴ表記）。Android の `android:label` と iOS の `CFBundleDisplayName` も `hima.`。Dart パッケージ名は `atsumaro` のまま。
- 温度感は `ok`（🙂）と `quiet`（🌙）の2種類だけ（`fire` は廃止）。マッチングは ok×ok のみで、quiet は自動マッチしない。
- やりたいこと（activity）は Bot と同じ `game` / `chat` / `work` / `out` / `any`。**任意項目**で、未選択は null。表示は単に `ひま`。
- 宣言時間はデフォルト60分、選択肢は **30分 / 1時間 / 2時間** のみ。
- 友達は「共通の Discord サーバーのメンバー」。友達申請・追加の導線は持たない。
- `さそう` は OS 共有シートではなく**アプリ内ノック**。受信・送信はヘッダーのベルの先に置く。
- タブは `ホーム` / `友達` / `プロフィール` の3つ。設定はヘッダーの歯車からも開ける。

## 1. プロダクトの方向性

**hima.** は、友達に「いま暇だよ」と気軽に伝え、暇な友達を見つけて誘うためのアプリ。

### コア体験

1. アプリを開く。
2. 大きなボタンを1回押して、**暇であることを宣言**する。
3. 友達の「暇」状態を見て、気になる友達を誘う。

**位置情報アプリではない。** whoo / Bump から参考にするのは、友達の存在感、テンポのよいUI、明るい配色、遊び心のある表現。**地図・GPS・常時位置追跡はUIにもMVP機能にも含めない。**

### デザインのキーワード

- **Friendly:** 仲のよい友達が自然に集まる空気感。
- **Playful:** 文字の勢い、少しだけ不規則な図形、小さなリアクション。
- **Instant:** 「暇を宣言」が最も簡単で目立つ操作。
- **Human:** 写真・名前・近況を重視。無機質な設定画面の集合にしない。
- **Clear:** 派手でも見やすさと状態の分かりやすさを優先。

### 避けること

- 地図を背景にすること、現在地・距離・「近くの友達」表示。
- 画面全体をパステルのグラデーションや大量のステッカーで埋めること。
- 意味なく光るボタン、過剰なドロップシャドウ、無関係な絵文字の乱用。
- 「いま、ひま！」なのに主ボタンが「ひまを宣言」のままになるなどの**状態矛盾**。
- 宣言のたびに質問への回答を必須にすること。

## 2. 最重要コピーと状態設計

ユーザーの状態に応じて、ホーム画面の**主見出しが変わる**。

| 状態 | 主見出し | 補助文 | メイン操作 | 補助操作 |
|---|---|---|---|---|
| **未宣言** | **いま、ひま？** | 「ひまなら友達に知らせよう」 | **ひまを宣言** | 任意で「なにする？」を選択 |
| **宣言中** | **いま、ひま！** | 「あと○分くらい」 | `おわる`（小さな二次ダブ） | 残り時間・温度感・やりたいことを変更 |
| **期限切れ直後** | **いま、ひま？** | 「ひま宣言が終了したよ」※一時表示 | **ひまを宣言** | なし |

### このコピーの原則

- `いま、ひま？` は、アプリからユーザーへの気軽な問いかけ。
- `いま、ひま！` は、ユーザー自身の状態を表す宣言。
- 句読点、全角の `！` / `？` を含めて統一する。
- 状態は**色と文字の両方**で伝える。色だけで区別しない。
- 宣言中に再度「宣言」を促すボタンは配置しない。終了は小さく静かな二次ダブにし、主役は見出しに譲る。

### 宣言のルール（MVP案）

- 最初の宣言は**ワンタップ**で成立。選択項目は必須にしない。
- 宣言時間はデフォルト **1時間**。宣言後に **30分 / 1時間 / 2時間** へ変更可能。
- 時間切れで自動的に「未宣言」へ戻す。端末側の表示だけでなく、共有される状態も終了させる。
- 「なにする？」は任意。未選択の場合は `なんでもOK` に決めつけず、単に `ひま` と表示する。
- ネットワークエラー時は成功扱いしない。元の状態を保って再試行できるようにする。

### 温度感の選び方

- **タップ**:「ひまを宣言」は直前まで使っていた温度感で即宣言する（初回は `ok`）。質問を挟まない。
- **長押し**: ボタンの周りに2つの温度感バブルが弧状に飛び出す。指を重ねたバブルが 1.3 倍に広がり、離すとその温度感で宣言する。外して離すとキャンセル。
- 宣言中はヒーローに現在の温度感をタップできるバッジとして出し、タップで小さなピッカーを開いて**同じセッション ID のまま**変更する。
- 初回のホーム表示時だけ「長押しで温度感を選べるよ」をボタンの近くに表示する。

**注意:** `yellow` 上の白い文字や `lime` 上の白い文字は避ける。基本は `ink` を使い、可読性を確認する。`heroDeclared*` 上の白文字は大きな太字（見出し）に限り、細かい文字は白いペイントダブに載せる。見出しは 34sp / w800 の**大きな文字**なので、WCAG のしきい値は 4.5:1 ではなく **3:1**。だから宣言中の塗りはブランドの明るいコーラル→ピンク（`#EE3F6A → #F0507A`、白に対して 3.8:1 / 3.4:1）でよい。以前は 4.5:1 を満たすために `#C2143F` まで暗くしていたが、必要のないコントラストのためにブランドの色が暗いクリムゾンになっていた。3:1 を割る明るさにするなら、見出しを `ink` に変えること。

### 3.2 タイポグラフィ

- **本文・見出し:** 丸みのある日本語ゴシック。**M PLUS Rounded 1c**（SIL OFL 1.1）を `app/assets/fonts/` に同梱して使う（500 / 700 / 800）。`google_fonts` は使わず、実行時にフォントをダウンロードしない。ライセンスは同ディレクトリの `OFL.txt`。
- 本文も同梱フォントにする。Android の Flutter は漢字をシステムフォントで補うとき、端末によって明朝体を選んでしまい（MIUI の Redmi Note 11 Pro 5G で確認）、1行の中でかなはゴシック・漢字は明朝になったため。アプリのロケールは `ja_JP` に固定している。
- **ロゴ `hima.`:** 別途ロゴアセットまたは太めの丸ゴシック。本文と異なる強い個性を許可。
- 画像の文字を単純なアウトライン画像で再現せず、**アクセシブルなTextウィジェット**を優先。

| Style | 目安 | Weight | 用途 |
|---|---:|---:|---|
| `logo` | 44sp | 900 | hima. |
| `heroTitle` | 36sp | 800–900 | いま、ひま？ / いま、ひま！ |
| `sectionTitle` | 23sp | 800 | いまひまな友達 |
| `friendName` | 18sp | 800 | 友達の名前 |
| `body` | 15sp | 500 | アクティビティ、本文 |
| `button` | 17–19sp | 800 | ひまを宣言 |
| `caption` | 12–13sp | 500 | 残り時間、補助テキスト |

- 見出しはコンパクトな行高、本文はゆったりめの行高を使う。
- 絵文字は説明の補助に留める。アイコンと絵文字をむやみに重複させない。
- Flutterの文字拡大設定に追従し、最低でも200%のテキストスケールで致命的な欠けを発生させない。

### 3.3 形・余白・線

| Token | 値 | 用途 |
|---|---:|---|
| `space4` | 4dp | アイコンと文字の最小間隔 |
| `space8` | 8dp | チップ内部、短い情報間 |
| `space12` | 12dp | カード内の要素間 |
| `space16` | 16dp | 標準の画面左右余白 |
| `space24` | 24dp | セクション間 |
| `space32` | 32dp | 大きなまとまりの間 |
| `radiusCard` | 24dp | カードの下地（実際の輪郭はペイント、3.4） |
| `radiusHero` | 32dp | 自分のステータスカード（実際の輪郭はペイント、3.4） |
| `minTapTarget` | 48dp | すべてのタップ領域の下限 |

- **ホームとボトムナビでは輪郭線を使わない。** 要素の境界はペイントの形・色・余白で示す。1.5〜2dp の枠線、ヘアラインの区切り線、アウトラインのピルはホームから廃止した。`borderWidth` はまだ他の画面（友達・設定・シート）が使っているが、それらも同じキットで塗り直す対象。
- 形は**絵の具の塊**にする。角丸の矩形や完全なスタジアムではなく、辺が短辺の 4〜10% 膨らみ・へこみ、四隅の丸みも揃わず、腕と雫を伴う不定形（3.4）。「わずかに揺らぐ」程度では矩形に見える。
- 影は弱く。情報のまとまりは影よりも余白と背景色で示す。カードに矩形の影やハイライトを付けない（ガラスに見える）。

### 3.4 ペイントキット（paint）

「ビチャ！」という絵の具の表現を、`lib/shared/widgets/paint/` の小さな `CustomPainter` プリミティブで作る。線で描いた落書き（`///`、波線、`!!`）は廃止した。

| プリミティブ | 用途 |
|---|---|
| `PaintSplat` | 飛沫。ボトムナビの選択タブの下地、小さな飾り |
| `PaintWash` | カード・セクションの下地。有機的な輪郭の塗り1枚に、内側の滲みと縁の溜まりを添えた水彩 |
| `PaintDab` | ボタン・ピル・チップの下地。潰れた歪な塊（`PaintSplat` の別名） |
| `BrushStroke` | 手描きの下線。中央が太く両端が細い、縁の粗いリボン |
| `BrushSwipe` | 太い筆で横にザッと塗った帯。ログインの下地（ヒーローは `PaintThick`） |
| `SplatterDots` | 小さな飛沫の散布。`///` の代わり |
| `PaintMark` | 星・ハートの小さな飾り。線ではなく塗りつぶした塊 |
| `PaintSwash` | 画面幅いっぱいの淡い滲み。ボトムナビでは使わない（4.5） |
| `PaintThick` | 厚みのある絵の具の塊。ヒーローと「なにする？」の塊。毛筋・艶・乾いた縁・ワイプ付き |

**飛沫の解剖：本体 + 腕 + 雫**

飛沫は「角丸の箱に雫を付けたもの」ではない。次の3つでできている。

1. **本体。** 角丸矩形の**中心線**を周長で等間隔にサンプリングし、各点を半径方向へ 2〜3 本の低周波サイン波（seed 付きの位相・振幅）でずらす。ずらし幅は**短辺の 4〜10%**。周長を基準にするので、横長カードでも長辺と短辺で揺らぎの空間周波数が変わらない（半径基準にすると長辺が1つの大きな膨らみになるだけだった）。**角の半径は4つとも別々**（0.55〜1.0 倍）にして、ひとつは丸く、ひとつは角ばらせる。四隅が同じ角丸矩形は、辺をどれだけ揺らしても矩形に見える。
2. **腕。** 本体の縁から外へ伸びる**先細りのローブ**を 3〜7 本。長さは短辺の 10〜30% が目安で、`paintMaxBleed` の予算に収まるところまで。根元が太く先端が丸い。根元は本体の内側に少し重ねるので、継ぎ目が見えない。**線で描かない**（`strokeWidth` を使わない）。塗りつぶした形の重なりだけで作る。先端が玉で終わるものもある。
3. **雫。** 本体から**完全に離れた**雫。大きいもの（直径 6〜14dp）と小さいもの（2〜5dp）を混ぜ、腕の方向に沿って並べ、遠いものほど小さくする。**首（ネック）は禁止。** 縁から雫まで細い線で繋ぐと、ピンやロリポップに見える（最初の版がこれだった）。繋ぎたくなったら、線ではなく塗りつぶした涙形にする。

**雫（ドリップ）** は任意で 1〜2 個。下辺から垂れる**塗りつぶした舌**で、先に玉が付く。これも線ではない。

**筆スワイプの解剖（`BrushSwipe`）：帯 + 不揃いな指 + かすれ筋 + しぶき**

太い筆で横にザッと塗った帯。ログインの下地はこれで、**飛沫ではない**（ヒーローは 4.2 の厚い塊）。飛沫は本体が矩形のままで、角・腕・ドリップという「突起」を足して有機的に見せていたため、「突起の生えた矩形のスライム」に読めていた。帯は突起を持たない。動きの始点と終点だけが形に出る。

輪郭は**承認済みのモックアップのアルゴリズムをそのまま移植**したもの。すべてのサンプル点を必ず通る1本の閉じた Catmull-Rom スプライン（tension 1/6、3次ベジェに変換）で描く。点の間を近似するだけの平滑化だと、指の先端が狙った位置からずれる。

1. **塗り始め（左）。** 筆が紙に着いたところ。帯の左端（`x0=4dp`）から左へ 3dp 膨らむ丸い塊で、上下は帯の高さの 25%（最大 14dp）内側の点を通る。矩形の角ではなく丸い肩になる。この左端は**箱の左端から 4dp で固定**なので、右端を箱に固定してはじめて帯が箱の中央に見える。
2. **上下の辺。** 上辺は `sin(x/41)*5dp`、下辺は `sin(x/33+1)*5dp` のゆるい波に、±2dp のジッターを足す。**周期も振幅も dp 固定**（帯の高さに比例させない）。振幅とジッターは、帯の縁と中身の縁の間の紙（`margin`）で頭打ちにする：辺が中身の矩形に入ると、ラベルの下に穴が開く。
3. **かすれ終わり（右）。** 帯が**不揃いな指**に割れる。**本数は帯の高さから決まる**（高さを 8〜26dp の指と 1.5〜4dp の隙間で埋める）ので、166dp の帯で約9本、高い帯では本数が増える。太さ・長さ・隙間はすべて **dp 固定**で、指ごとに違う：太さ 8〜26dp、長さは帯の端から 6〜40dp。各指は**丸い先端**で終わる（尖らせない、四角に切らない）。指の間の隙間は塗りの中へ切り込むので、右端は垂直な線にならない。**本体の右端は「箱の幅 − 14 − 最大の毛先の長さ」**で、いちばん長い毛先が箱の右端から 14dp のところまで届く。その手前の 14dp はしぶきの余白。狭い箱では毛先の長さを比例して縮める（`_swipeFullWidth` 未満）。
4. **かすれ筋。** 帯の中の細い紙色の筋（高さ 1.4dp）を 6 本、**本体の最後の 12〜20dp（16dp）**に、筆の進行方向（水平）に沿って置く。これは**塗りからくり抜いた穴**で、上に紙色を描くのではない。下に何があっても（紙でも、未宣言の帯でも）正しく透ける。中身の右端より左には置かない。
5. **濡れの艶。** 帯の上半分に、白の低アルファの縦グラデーションを1枚（ピーク 8%、帯の高さの上の 42% で 0 まで）。形ではなくグラデーションなので縁が無い。帯のパスでクリップする。**濃くしない。** 帯の上に直接文字を載せることがあり、艶で明るくするとそのコントラストが落ちる。今の値なら見出しが載る範囲でいちばん悪いところでも十分な比を保つ。
6. **しぶき。** 帯の終わりから**コーン状に散らす** 16 個。**縦に並べない**（縦一列は直線に見え、ユーザーが嫌った形）。毛先の先あたりから箱の右端までの帯に置き、縦位置は帯の高さの ±(10〜38)% に散らす（奥ほど広がる円錐）。大きさは円錐の奥へ行くほど小さくなり、近いもので半径 2〜4dp、遠いものは 0.8dp。箱の外に出る雫は描かない（画面端で切らない）。

**厚い絵の具の解剖（`PaintThick`）：本体 + 毛筋 + 艶 + 乾いた縁 + ワイプ**

ヒーローの下地と「なにする？」の塊。帯（`BrushSwipe`）は「横から見た矩形」に見えるので、見出しを載せる面には使わない。

1. **本体。** 飛沫と同じ生成器（seed・キャッシュ・セーフレクト）で、腕と雫は同じ解剖（上記）。塗りは2色のグラデーションで、上端が明るく下端が濃い。
2. **毛筋。** `paint_streak.jpg` を `paintDetail` で中だけに敷き、`softLight` で明度だけを乱す。**色は足さない**：塗りの色は `AppColors` のままで、毛筋は明るい筋と暗い筋として出る。粒（`paper_grain.jpg`）を `overlay` で薄く重ね、大きな平らな塗りが印刷に見えないようにする。**文字の下では薄くする。** 明るい筋は塗りを持ち上げるので、白文字が載る面（宣言中のヒーロー）では中身の矩形の内側で毛筋を淡くし（`detailUnderContent`）、塗りの縁の帯にだけ濃く出す。境目は放射グラデーションのマスクでぼかすので、直線の継ぎ目は出ない。
3. **艶。** 本体の上のほうに白 7% の縦グラデーションを1枚。その上に**硬いスペキュラ**と**濡れた縁**を置くが、置き場所は**セーフレクトの外の帯だけ**にする：宣言中のヒーローは白文字を直接塗りに載せており、艶で塗りが明るくなると 3:1 を割る。縁の外側には文字が無いので、そこだけ光らせれば「厚い塗りの照り」になり、ラベルは一切明るくならない。下端には濃い溜まりを1本入れて厚みを出す。
4. **乾いた縁。** `paint_drybrush.jpg` の**輝度をアルファとして** `dstOut` で縁の帯から削る（`saveLayer` の中で行う。ルートレイヤーに描くと紙まで抜ける）。輪郭は「滑らかなシルエット」ではなく、刷毛で引きちぎられた塗りになる。
5. **ワイプ。** `wipe`（0→1）で塗りが**左から落ちる**。前線は seed 付きの不揃いな縦線と数本の指（`paintWipeRegionPath`）で、直後の 40dp を `paint_drybrush` で削って「乾いた筆で拭いた跡」にする。塗りだけでなく、その上の中身も同じ前線（`paintWipeKeptPath`）でクリップする。保持側は箱の外まで含むので、箱からはみ出した腕や雫も切られない。

**テクスチャ（`paint_texture.dart`）**

`assets/textures/` の3枚（`paint_streak` / `paint_drybrush` / `paper_grain`、512/384px、グレースケール、タイル可能、CC0 1.0。出典は同ディレクトリの `LICENSES.md`）。**画像は追加しない**。

- デコードは `PaintTextures` が**1回だけ**行い、全ペインターで共有する（512px、タイルするので縮小しない）。毎フレームのデコードはしない。
- **色は持たせない。** `paintDetail` は `softLight`（中間グレーが無変化）で塗りの明度だけを乱し、`paintDetailErase` は輝度を被覆に変えて `dstOut` で削る。どちらも塗りの色は `AppColors` のまま。
- **無いときは平らな塗り。** デコード前・アセット欠落・失敗のいずれでも `null` が返り、ペインターは平らな塗りを描く。空白にもエラーにもしない。

**中身の安全（content safety）**

- 呼び出し側は中身の矩形を渡す（`child` を渡せばウィジェットが測る）。**塗りつぶしの帯は中身 + `padding` を完全に覆う。**
- **指・隙間・かすれ筋・しぶきは、中身の右端より右でしか始まらない。** 文字の下に穴や筋が走ると取り消し線に見える。
- そのため帯は中身の右に **`paintSwipeContentInset(width)`（14 + 最大の毛先 + かすれ区間。フル幅で約 70dp）** を確保する。中身の右の余白は **`max(padding.right, この値)`** で、**足し算にしない**（足すと中身が帯の中心より左へ寄る）。狭くなった分は `Wrap` と折り返しで吸収する。
- **中身の左右のそろえ。** 右だけに余白があるので、中身は放っておくと帯の中心より左に寄る。ログインは `BrushSwipe(centerContent: true)` で左にも同じ余白を入れ、下の中央そろえの文とボタンに軸を合わせる。中身が狭くなるぶん、帯の箱だけ左右へ広げてよい。
- 揺らぎとジッターは、**帯の縁と中身の縁の間の紙の余白（`margin`）** を上限にする。余白を食い尽くすと中身の下に穴が開く。

**画面に収める（fit）**

- **帯・指・しぶきは、すべてウィジェットの幅の中に収める。** これは飛沫と逆の方針。飛沫は画面外へはみ出してよいが、**画面端で切れた帯は矩形に戻って見える**。
- 幅が足りないときは、**指の長さとしぶきの距離を同じ比率で縮める**。クリップしない。
- しぶきは帯の内側に収める。呼び出し側は帯のまわりに `paintSwipeBleed`（18dp）の紙を確保する（帯の縁の揺らぎと、傾けた2回目の帯のため）。ログインは上下 32dp を空けている。ヒーローは帯ではなく `PaintThick` なので `paintThickBleed`（24dp）を使う（4.2）。
- 帯の高さは中身に追従する（文字拡大で帯も伸びる）。

**作り方の原則**

- **seed で決める。** すべての形は `int seed`（`paintSeedOf(名前やID)`）から決まる。`Random()` を描画時に呼ばない。カードは再ビルド・ポーリング・スクロールで同じ輪郭を保ち、同じ友達はいつも同じ飛沫になる。
- **パスはキャッシュする。** (seed, サイズ, 設定) をキーに一度だけ生成して使い回す。スクロール中に輪郭を毎フレーム再サンプリングしない。
- **セーフレクト。** `child` は `padding` ぶん内側の矩形に収め、ペイントはその外側の帯まで広がる。腕・雫・ドリップは必ずセーフレクトの外に置くので、文字やタップ領域を覆わない。角丸の半径は `padding` から上限を解いて決めるため、どれだけ丸くしても中身を削らない。揺らぎの内側半分はセーフレクトの位置で頭打ちにするので、形が中身に食い込むことはない。
- **ペイントはウィジェットの箱からはみ出してよい。** 揺らぎと腕を箱に収めようとすると、揺らぎを小さくするしかなくなり、直線が戻ってくる。はみ出す分は呼び出し側が余白で用意する（`Stack(clipBehavior: Clip.none)`、レイアウトの隙間、画面端へのブリード）。**帯（`BrushSwipe`）だけは例外**で、幅は箱に収める（3.4 の「画面に収める」）。
- **はみ出し量には上限がある。** 揺らぎ・腕・先端の玉・雫はすべて `paintMaxBleed`（40dp）に収まるよう頭打ちにしてある。割合だけで決めると、大きな箱や文字拡大時にどこまでも外へ伸びて隣の要素に乗ってしまう。呼び出し側は `paintMaxBleed` ぶんの余白を確保すればよく、形を測る必要はない。**帯（`BrushSwipe`）はこの値を使わない**：しぶきは帯の内側に収まるので、必要な余白は `paintSwipeBleed`（18dp）だけ。**厚い塊（`PaintThick`）は `paintThickBleed`（24dp）** で足りる：ヒーローの腕と雫は短く、40dp の予算を使い切らない。ホーム画面はヒーローの上下にこの値を使っている（マッチカードの有無にかかわらず）。
- **`PaintWash`（カード）も同じ生成器**を使い、揺らぎを 2〜5% に落とす。角の半径は4つとも違い、腕は 0〜2 本の短いもの。矩形の影やハイライトは**置かない**（それが「ガラスっぽいカード」の正体だった）。
- **洗いは1枚で塗る。** 同じ色相の半透明ブロブを2〜3枚ずらして重ねると、縁が2〜3本の平行線として見え、矩形の輪郭をなぞってしまう（「輪郭が何本もあるすりガラス」に見えた原因）。塗りは1枚だけにし、tonal variation はその内側で作る。内側の滲みは輪郭を持たない放射グラデーションで、本体のパスでクリップする。溜まりの線も**1本だけ**、実際の輪郭に沿わせる。ずらした写しを重ねない。
- **アニメーション低減。** 動くプリミティブは `progress`（0→1）を受け取り、`MediaQuery.disableAnimationsOf` が真なら最終状態を静止画で描く。

**モーション**

- **`PaintSplat` の `progress`。** 本体は `minScale`（既定 1）から基準サイズへ飛び込み、オーバーシュートして着地する。腕は根元から 1 本ずつ伸び（軸方向だけをスケールするので幅は変わらない）、雫が縁から飛んで所定の位置に着地し、ドリップが少し遅れて伸びる。`origin` を渡すと、その位置を中心に育つ（「なにする？」の滲みはシートの上端から飛ぶ）。
- **`BrushSwipe` の `progress`。** 筆を左から右へ走らせる。塗りは**柔らかく裂けた前線**（seed 付きの揺れる縦線）でクリップされて現れ、**しぶきは筆が帯の終わり（`bodyRight`）に届いてから**順に飛ぶ（`PaintSwipe.splatterAt`）。前線を直線にすると「図形をワイプしている」ように見えるので、必ず揺らす。`MediaQuery.disableAnimationsOf` が真なら完成形を静止画で描く。
- **`PaintThick` の `progress` と `wipe`。** `progress`（0→1）は塗りの着地で、本体は**1倍を下回らない**（中身は常に塗りの上）が、腕が1本ずつ外へ伸び、雫が飛び、5%だけオーバーシュートして着地する。`wipe`（0→1）は塗りを**左から拭き取る**動きで、前線は `paintWipeRegionPath` の不揃いな縦線、直後を `paint_drybrush` の輝度で `dstOut` して乾いた筆の跡にする。`MediaQuery.disableAnimationsOf` が真なら完成形（とワイプなし）で描く。
- **ワイプは塗りと中身で同じ前線を使う。** `paintWipeKeptPath` は塗りを切り抜くのと同じパスを返すので、その上の白い見出しとメタ行もこれで切る。切らないと、塗りが去ったあとに白文字だけが淡い下地に残り、約 1.1:1 まで落ちる（4.2）。
- **帯の上に載る文字も同じ前線でクリップする。** `paintSwipeRevealPath` は塗りを切り抜くのと同じパスを返すので、中身もこれで切れば「塗りが届いたところにだけ文字が出る」ことになる（ログインの帯がこれで、帯の箱の中心に中身をそろえている）。
- **中身を載せる飛沫は `minScale: 1`。** 本体が 1 倍を下回らないので、アニメーション中も中身は必ずペイントの上にあり、文字のコントラストが落ちない。飛び込みを見せたいときは、不透明な塗りの上に `minScale < 1` の装飾用の飛沫を重ねる。装飾用の飛沫は塗りより**濃い**色にする。淡くすると白文字が 3:1 を割る。ヒーローの厚い塊（`PaintThick`）は飛沫と違い、**塗りそのものが着地し、`wipe` では中身も同じ前線で切られる**ので、文字が下地の上に残る瞬間がない（4.2）。
- それ以外のプリミティブは静止画。スクロールする一覧に無数のコントローラを載せない。

**置き場所**

- 装飾は余白の帯に置く。文字の上には置かない。
- 画面全体で 5〜8 箇所。均等に並べず、左右非対称に散らす。カードは全部には付けず、2〜3枚に1つ程度。
- 意味は持たせない。読み上げ対象から外し（`ExcludeSemantics`）、ポインタも無視する。色は状態を表さない。
- **帯（`BrushSwipe`）を使うのはログインだけ。** ヒーローは `PaintThick`（厚い塊）で、見出しを載せる面が帯だと「横から見た矩形」になるため（4.2）。ログインはレモン→空色の帯を先に敷き、その上にレモン→コーラルの帯を**数度傾けて**重ねて、2回塗った跡に見せる。中身（ロゴと `いま、ひま？`）は手前の帯のセーフレクトに載せるので、傾けた奥の帯が文字の下に来ることはない。奥の帯は傾きぶんだけ上下にはみ出すので、下の説明文とは `AppSpacing.s32` 空ける。中身は `centerContent: true` で帯の箱の中心にそろえ、下の文とボタンと同じ軸にする（左右の余白のぶん狭くなるので、帯の箱だけ外側の 24dp 余白の内側へ横 12dp ずつ広げる。それでも 320dp 幅では中身が約 170dp しかなく `いま、ひま？` は 36sp では収まらないので、見出しは `FittedBox(scaleDown)` で**1行のまま縮める**。折り返さない。収まる幅では 36sp のまま）。

**色**

- ペイントは単色で塗らない。2色のグラデーション（左上→右下）か、同系色の内側の滲みで tonal variation を持たせる。
- カードの下地には、縁にわずかに濃い「溜まり」の線を**1本だけ** `MaskFilter.blur`（半径 1.4dp 程度）で添える。枠線ではなく水彩の縁。2本目を足すと輪郭が二重に見える。
- 下線（`BrushStroke`）の色は、洗いを暗くした色ではなく、パレットの彩度のある色（ラベンダー／紫・ミント・コーラル・レモン・空色）から取る。パステルを黒へ寄せると彩度が落ち、ミントの下線が灰緑、ピーチの下線が灰茶になった。下線は装飾（文字は載らない）なのでコントラスト比の対象外。
- ぼかしは小さく保つ。ホームは何枚もスクロールするので、大きな半径のぼかしは使わない。

**一覧・設定・セグメント**

- **一覧は枠も区切り線も持たない。** サーバーや設定のまとまりは1枚の `PaintWash`（seed はサーバーIDや項目名から取る）に載せ、行と行は余白だけで分ける。見出しの下には `BrushStroke` を敷く。
- **ノック画面・設定画面のタイトルも同じ下線を持つ。** `AppBar` のタイトルはタブ見出しと同じ「見出し＋`BrushStroke`」の組にする。ツールバーの高さは文字拡大に合わせて伸ばす（既定の 56dp のままだと 200% で下線が切れる）。戻るボタンとその読み上げは標準のまま残す。
- **検索フィールドは `PaintDab`。** 角丸の矩形ではなく、潰れた有機的な塊にする。形の生成器は角の半径を `padding` から解くので、`padding` を 0 にすると角が直角に戻り、直線の辺が見えてしまう。フィールドにも必ず内側の余白を持たせる。
- **設定の行は Material の `Switch` のまま。** 下地だけを塗りに変え、読み上げと操作は標準から動かさない。
- **セグメント（受信／送信）は淡いトラックに白いピルを置かない。** 選択中の側にだけ紫のダブが着地し、もう片方は紙の上の文字だけにする。
- **ボタンは `PaintDab`。** 主操作は紫のダブに白文字、副次操作はインク文字の淡いダブ。洗いの上では洗いと同系色を避ける（ノックの返事は空色。ミントは「いいよ！」の色）。無効時は `mutedSoft` にインクで、文字を薄めない。
- **洗い（wash）の上の文字は一段暗くする。** パステルの洗いは紙より暗いため、`muted` のままだと 4.5:1 を割る。

## 4. ホーム画面

### レイアウト順

1. **Header:** `hima.` ロゴ、通知、設定への導線。
2. **My Status Hero:** `いま、ひま？` / `いま、ひま！` が最も目立つ領域。未宣言は「見出し + 説明 + ひまを宣言 + `なにする？` チップ」、宣言中は「アバター＋見出し + メタ行 + `おわる`」（4.2）。
3. **Match Cards:** マッチした**種類ごとに1枚**（最大3枚）。
4. **Friends Section:** `いまひまな友達` と人数バッジ、友達カード。
5. **Bottom Navigation:** `ホーム` / `友達` / `プロフィール`。

**初期画面で絶対に見せるもの：** 自分の状態、宣言操作、暇な友達が何人いるか。全友達カードの表示は縦スクロール可。

### 4.0 レイアウトの決定事項（実機レビューより）

- **`なにする？` をヒーロー内へ移動。** 以前は Friends Section の下にあったため、宣言の前後でやりたいことを選ぶには友達グリッド全体をスクロールする必要があり、実質的に隠れていた。任意項目であることは変えず、未宣言では塊の直下に置き、通常幅では横スクロール、狭幅や大きな文字では折り返す（4.4）。
- **ヒーローは「カード＋ボタン」ではなく、押せる絵の具の塊。** 帯（`BrushSwipe`）＋黄色い「ひまを宣言」ダブは、隣のカードと並ぶと「横から見た矩形と、その下のボタン」に見えていた。塊（`PaintThick`）1つに変え、`いま、ひま？` と `タップで宣言` をその上へ載せ、塊全体を1つのボタンにした（3.4・4.2）。宣言の終わりは色を戻すのではなく、塗りを乾いた筆で拭き取って戻す（4.2）。
- **マッチカードは種類ごとに1枚。** 1人1枚だと人数分並び、`いまひまな友達` が画面外へ押し下げられ、しかも同じ人が下のグリッドにもう一度出ていた。カードは種類のメッセージを見出しにし、該当する友達のアバターを名前付きで横に並べる（最大5人、残りは `+N`）。種類は見出しのアイコンと文言だけで示し、アバターの横に浮かせた絵文字は置かない（誰の温度感か分からなくなるため）。温度感はアバターごとのバッジにする。
- **マッチカードも友達カードと同じ言葉で描く。** 細い枠の白い箱は、隣のヒーローや友達カードの横で入力フォームに見えていた。パステルの下地（🙂×🙂 はスカイ）と、右上に小さな塗りダブ（`PaintMark`）を置く。見出しは種類の絵文字ペア + 一文。アバターは白いリング付きの 56dp（友達カードと同型）に温度感バッジを添え、`さそう` / `さそった` / `いいよ！` は各アバターの直下に置く。色は種類の区別を助けるだけで意味は持たせず、内容は必ず文言でも示す。
- **アバターは入るときは等間隔、入らないときは折り返す。** 左に寄せると右半分が空いて見え、逆に縮めると下のダブが読めなくなる。入る枚数なら `spaceEvenly` で配り、超えたら幅を保って次の行へ回し、誘う操作をカードの端で切らない。
- **残り時間とやりたいことは見出しの直下の1行。** 以前はカード下部に中央寄せで浮いており、見出しと結び付いて見えなかった。宣言中は見出しの下のメタ行にまとめ、`Wrap` で大きな文字サイズでも折り返す。温度感はアバターのバッジに移した（4.2）。
- **宣言中は要素を3つに絞る。** 温度感のピル・全幅の終了ボタン・チップ列が積まれて見出しが埋もれていたため、宣言中は「アバター＋見出し」「メタ行」「`おわる`」だけにし、チップ列はメタ行の1ダブへ畳む（4.2）。`おわる` はメタ行と同じ `Wrap` に並べる。独立した行に置くと下段の左半分が空いてカードが縦に伸び、しかもダブが飛沫の右下の丸みに食い込んで切れて見えた。

### 4.1 Header

- 左：太くて丸い `hima.` のワードマーク。
- 右：通知ベル（未確認のノックや結果があると赤いドット）、設定アイコン。
- ベルのドットは、受信は一覧を表示した時点で、送信は結果を表示して既読にした時点で消える。
- ベルはノック画面（受信／送信）を開き、歯車は設定を開く。設定はプロフィールタブにも並ぶ。
- アイコンボタンのタップ領域は最低 **48×48dp**。
- ロゴ以外の装飾は少なくして、主役をステータスに譲る。

### 4.2 My Status Hero

ホームの視線の中心。自分のアバターを大きめに表示して、状態をひと目で判断できるようにする。背景は角丸の矩形でも帯でもなく、**厚みのある絵の具の塊（`PaintThick`）**にする（3.4 の解剖）。未宣言は淡いラベンダー→レモン、宣言中は**同じ塊**を明るいコーラル→ピンクで塗り替える。白い見出しは 34sp / w800 の大きな文字なので 3:1 で足りる（3.1 の注意を参照）。

**2つの状態は同じ塊。** seed も腕も雫も同じなので、宣言中の塗りは未宣言の塗りを端まで完全に覆う。だから「ビチャ」の着地も、終了のワイプも、下の状態が縁からのぞかない。中身の余白（`heroBlobPadding`）も両状態で**同じ1回だけ**：未宣言は塊のペイントが中身を内側に置き、宣言中は中身を載せる側が同じ値を1回入れる。片方だけ二重になると、片方の文字だけ早く折り返して塊の形も変わってしまう。塊は中身の高さに追従し、`AnimatedSize`（260ms）でその差を吸収するので、下のカードが跳ねない。

見出しは装飾として 28〜42sp の範囲で文字スケールに追従する。説明・操作ラベルなど本文はユーザー指定の文字サイズを保ち、折り返しに合わせて塊を伸ばす。

**未宣言（OFF）: 塊そのものがボタン。** アバターと見出しを塊の上に置き、`タップで宣言` のラベルを白いダブに載せる。塊全体が1つのボタン（読み上げ名 `ひまを宣言`）で、押すと直前まで使っていた温度感で即宣言する。長押しは温度感のバブル（2節）だが、スクリーンリーダーは長押しできないので同じ選択をカスタムアクションとして公開する。押しているあいだ塊は 0.975 倍に縮み、失敗すると塊ごと横に揺れる。以前の黄色い「ひまを宣言」ボタンは無い。

**宣言中（ON）:** 「祝福のメッセージを1つ読む」だけの面にする。要素は次の3つに限る。

1. **アバター + 見出し**：アバターの右下に温度感の絵文字バッジ（26dp 表示、タップ領域は 48dp）。タップで温度感ピッカーを開く。見出しは白・数度傾けた **`いま、ひま！`**、その下に白いブラシストローク（`BrushStroke`）。
2. **メタ行**：残り時間 `あと59分` と、やりたいこと `ゲーム`（未選択なら `なにする？`）。どちらも白いペイントダブで、タップで変更できる（時間は 30分 / 1時間 / 2時間、やりたいことはシート）。残り時間は「くらい」を落とした短い形（`himaRemainingShortLabel`）にする：3つで1行を分け合うので、`あと1時間くらい` は情報を増やさずに一番幅を取るだけだった。
3. **`おわる`**：メタ行の最後に並べる、小さく静かなダブ。48dp のタップ領域は保つ。3つは1つの `Wrap` に入れる。411dp 幅では「残り時間 + やりたいこと」と「`おわる`」の2行に折り返す。それでも `おわる` を独立した行にはしない：独立行にすると下段の左半分が空いて塊が縦に伸びる。

- `なにする？` のチップ列は宣言中は出さない。選んだものはメタ行に1つだけ出す（4.4）。
- 温度感を独立したダブとして並べない。バッジとメタ行で足りる。
- 温度感バッジの絵文字は**文字拡大に追従させない**。円はアバターの角に載る固定サイズなので、絵文字だけが大きくなると円からはみ出して欠けて見える。温度感は読み上げラベル（`Mood.label`）が伝える。
- 全幅の終了ボタンは置かない。宣言中に「ひまを宣言」を再度促すボタンも置かない。
- 宣言直後の短いリアクションアニメーションを表示（6節）。

**宣言のアニメーションは塗りの着地。** コーラルの塊が「ビチャ」と落ちる：本体は1倍を下回らないので見出しの下は常に塗りで、腕が1本ずつ外へ伸び、雫が飛ぶ（約520ms）。白文字が淡い下地に載る瞬間は無い（3.4）。触覚は宣言成功時（6節）。

**終了は塗りを拭う。** `おわる` を押すと、約700msかけてコーラルの塗りが**左から乾いた筆で拭き取られ**（`paint_drybrush` の前線）、下から未宣言の塊と `いま、ひま？` が現れる。塗りだけでなく、その上の見出しとメタ行も同じ前線でクリップするので、白文字が淡い下地に残る瞬間は無い。塗りは**終わり際（約9割）で一度止まり**、`endHima` が通ってから最後の一拭きで消し切る：返事が来ていないうちに紙の状態を出し切らないので、失敗しても OFF が一瞬見えて ON に戻ることはない。失敗したら塗りは同じコントローラで戻り、宣言中の見た目はそのまま復元される（エラーのスナックバーは従来どおり）。**ユーザーの `おわる` だけがワイプを起こす**：期限切れやサーバー起点の変更は今までどおり即座に切り替わる。

- **アニメーション低減**（`MediaQuery.disableAnimations`）では、ワイプも「ビチャ」も出さず、そのまま切り替える。

**重要：** 画像の赤いカード内に `いま、ひま！` と `ひまを宣言` が同居する表現は採用しない。**状態に応じた一貫したUI**へ修正する。

### 4.3 Friends Section

- セクション名：**`いまひまな友達`**。人型アイコン、ライムの人数ダブ、文字の下に紫のブラシストローク、右端に小さな飛沫（`SplatterDots`）。
- カードは原則**2列グリッド**。幅が足りない端末では1列、または縦型レイアウトへ適応。
- 友達カードの下地は**`PaintWash`**（枠線なし）。有機的な輪郭の塗り1枚に、内側の滲みと縁の溜まりを1本だけ添える（3.4）。形は友達 ID から seed を取るので、再ビルドやスクロールで変わらない。
- 友達カードは、白いリング付きの丸アバター（右下に温度感の絵文字バッジ）、名前、残り時間、やりたいことのダブ、`さそう` ダブで構成。
- やりたいことのタグは**白いペイントダブ + そのカテゴリの色のアイコン**（ゲームはコントローラ、通話は電話、作業はノートPC、外出は歩く人、なんでもは星）。カードの下地はパステルで回転するため、タグの下地までパステルにすると同じ色のカードで見えなくなる。色はアイコンで示す。
- カードの2〜3枚に1枚、小さなハートや星の塗りダブを添える（3.4）。
- `さそう` は宣言中の友達にのみ表示。未宣言の友達の行動を推測する表示はしない。
- ノックを送った相手は、返事が来るまで `さそった`（チェック印・淡い下地・押せない）に変わる。二重に誘えないようにするため。
- 返事が `いいよ！` なら、その相手は**ミントのダブ**にする。以前は返事が届いた瞬間に `さそう` へ戻り、承諾されたことが画面から消えていた。この状態は**その宣言が続いているあいだだけ**保ち、`ひまを終了`・期限切れ・宣言し直しのいずれでも `さそう` に戻す（サーバーは返事を保持し続けるので、アプリ側で「今回の宣言の約束」として畳む）。
- 友達がゼロ人なら、空のグリッドの代わりに `まだひまな友達はいないよ` と案内する。
- 写真未設定の友達は、名前から選んだパステルのグラデーションにイニシャルを載せたサークルで代替する。

**`さそう` の3状態（`KnockPill`）**

| 状態 | 下地 | 文字 | コントラスト |
|---|---|---|---|
| `さそう` | `purple` のダブ | 白 | 6.3:1 |
| `さそった` | `mutedSoft` のダブ | `ink` | 12.6:1 |
| `いいよ！` | `mint` のダブ | `ink` | 12.0:1 |

**Friend Card の例**

```text
(ゆるい塊の下地。枠線なし)
  (写真)  ゆう
          あと40分
  [🎮 ゲーム]      ♡
  [     さそう     ]
```

アバターは左に大きめ（56dp + 白いリング）、名前・残り時間はその右に縦に並べ、やりたいことのダブと `さそう` はカード幅いっぱいに置く。

カードの色は友達ごとに薄紫・水色・ピーチ・ミントをローテーションしてよい。**色そのものに意味は持たせない**（状態は文字で表現）。

### 4.4 「なにする？」チップ

- 置き場所は**ヒーローの塊の下、紙の上**（4.0）。**未宣言のときだけ**出す。塊の中に置くと、横スクロールする列が塊の縁で切れて見え、その切り口をフェードで隠すとチップのラベルのコントラストまで落ちる。紙の上なら列はスクロールビューの端で切れるだけで、ラベルは常に不透明のまま。
- 候補：`ゲーム` / `雑談・通話` / `作業通話` / `外出` / `なんでもOK`（Bot と同じ値。`game` / `chat` / `work` / `out` / `any`）。
- チップは**カテゴリごとに色とアイコンを変える**（`ActivityStyle`）。同じ白いチップを並べない。下地は小さなペイントダブ。
- 選択中は**その色をアクセント方向へ寄せた濃いダブ**にし、飛沫を1〜2個添える。枠線では示さない。
- 未選択（null）を許す。API でも任意項目で、未選択は `ひま` と表示する。
- 宣言の**必須条件にはしない**。選ばなくてもすぐに宣言できる。
- 未宣言でチップを押した場合は、選択内容を保持するだけ。勝手に宣言しない。
- 宣言中はチップ列を出さず、選んだものをメタ行の1つのダブに畳む（4.2）。タップで同じ選択肢をシートに出す。宣言中に選び直した場合は、共有しているカテゴリを更新する（更新成功後に反映）。
- そのシート（`showActivityPicker`）は**紙の上に絵の具を飛ばした画面**にする：柔らかいピンクの滲みが**押したコントロールの位置から**飛び出し、雫が飛び散り、5つの塊が**弾みながら着地**する（1つずつ順番をずらす）。`showActivityPicker` の引数は増やさない（呼び出し元はヒーローとデモパネルの両方）ので、直前に押された点をアプリ側（`ActivityPickerAnchorListener`）が記録し、シートはその点を滲みの箱へクランプしてから滲みの原点にする。塊は `PaintThick` の小さなダブで、`ActivityStyle` のパステルを同じ色相のまま一段濃くしてある（そのままだと滲みの上で半透明に見える）。選択中の塊は**ひと回り大きく、チェック付き**。塊はどれも 48dp 以上で、`Semantics(button:, selected:)` を持つ。選ぶと閉じる。背景のタップと戻る操作で閉じられる。選択肢は**アプリの5つだけ**（サーバーは未知の値を拒否する）。「なし」は、すでに選んでいる場合にその選択を消すための小さなダブとしてだけ出す。
- 一度に選択できるカテゴリは、MVPでは**1種類**。未選択に戻せる。
- 300dp 未満の幅または文字スケール 1.3 超ではラベルを先頭に置き、チップを複数行へ折り返して末尾が切れないようにする。それ以外では横スクロール可能。列は紙の上にあるので、通常幅で右端が切れる場合も帯の縁でラベルのコントラストを落とさない。

### 4.5 Bottom Navigation

- タブは `ホーム` / `友達` / `プロフィール` の3つ。
- **帯にしない。** 背景の形は置かない。タブは紙の上に直接乗せ、箱の上端だけ「透明 → 紙」の縦グラデーションでぼかす。画面幅いっぱいの形（直線でも波線でも）を敷いた時点で、それはバーに見える。以前の淡い紫の帯がまさにそれだった。
- **フェードは固定の高さ（56dp）で持つ。** ナビの高さに対する割合にすると、文字拡大でナビが伸びたときにフェードの帯まで伸び縮みする。48〜72dp の範囲なら、スクロールしてきた内容が紙に溶けて消え、直線の縁が見えない。フェードの下は紙で塗りつぶす。
- 選択中：**そのタブの色の小さな飛沫（`PaintSplat`）をアイコンの背後に敷く**。ホームはコーラル、友達はミント、プロフィールはレモン。本体 + 短い腕 1〜2 本 + 雫 2〜3 個のミニ飛沫で、**ドリップは付けない**（ラベルの上に垂れる）。腕も短くして、下向きの腕がラベルに届かないようにする。
- 切り替え：新しい飛沫が `progress` で飛び込み、前の飛沫は縮んで消える。`lib/shared/haptics.dart` の `selectionClick` を1回。
- 非選択中：アイコンとラベルは紙の上にそのまま。色は `ink` の 68%（紙に対して約 5.7:1）。60% だと 4.4:1 で、13sp のラベルは 4.5:1 を割る。
- ラベルは常に見える。**文字拡大は頭打ちにしない。** 200% では 2 行に折り返して見せ、省略記号にしない（ナビの高さが伸びるだけでよい）。
- `SafeArea` と下端インセットを保ち、各項目のタップ領域は 48dp 以上。`Semantics(selected:, button:, label:)` を付ける。
- **内容はナビの下をスクロールする。** `Scaffold` の `extendBody` を有効にし、本文をナビの下まで伸ばす。本文をナビの上で切り取ると、リストの末端がナビの上端で定規で引いたように切れ、それがまさに廃止したい直線になる。切り取りの代わりに上のフェードで溶かす。
- **一覧の下端は余白で逃がす。** ナビは内容の上に浮くので、各タブは一覧の下端に「ナビの高さ + 32dp」を確保する。高さは `MediaQuery` の下端パディング（`extendBody` のときスキャフォールドがナビの高さを報告する）から取る。固定値にすると、200% でラベルが2行になってナビが伸びたときに最後の項目が隠れる。
- ボトムナビは常に表示。

## 5. 他画面（MVPの最小限）

### 友達

- 友達 = 共通 Discord サーバーのメンバー。友達申請・追加の導線は持たない。
- サーバーごとにまとめて表示し、各サーバー内で `ひま` の人を先、そうでない人を下に並べる。
- 名前検索を上部に置く。
- 公開設定がオフのサーバーには `非表示` と表示する。
- `さそう` は `ひま` の人にだけ出す。ひまかどうか分からない相手の状態を推測しない。

### プロフィール

- アバター、表示名。
- 設定（自動ひま提案（Android のみ。スイッチ、通知までの利用時間、対象アプリ、使用状況と通知の許可、「Discordでも受け取る」（オンにしているときだけ））、サーバーごとの公開、マッチングしない人、よくひまな時間）、ログアウト。
- 自動ひま提案は通常サイズではタイトル・説明・スイッチを1つの設定行に置く。文字拡大時はタイトルとスイッチの下へ説明を全幅で置き、本文を縮めず句読点も単独行にしない。
- ヘッダーの歯車からも同じ設定を開ける。

### 誘う（アプリ内ノック）

- `さそう` タップ → 小さなボトムシートを表示。
- 友達の名前とやりたいことを表示し、テンプレ（`ゲームしない？` / `ちょっと話さない？` / `作業通話しない？`）を1つ選んで送る。
- quiet の相手には `スルーしてOK` を添える。
- 受信・送信はヘッダーのベルの先のノック画面にまとめる。受信は `いいよ！` / `あとで` / `今回はパス` で返す。送信は状態を表示し、未確認の結果は一度だけ強調してから既読にする。

## 6. モーション・リアクション

遊び心は「意味のある瞬間に1回だけ」出す。常時動く演出は使わない。

| 瞬間 | 動き | 触覚 |
|---|---|---|
| 塊（`ひまを宣言`）を押す | 塊が 0.975 倍に縮み、オーバーシュートして戻る | — |
| 宣言成功 | コーラルの塊が「ビチャ」と着地する：本体は 1 倍を下回らずに 5% オーバーシュートし、腕が 1 本ずつ外へ伸び、雫が飛ぶ（約520ms）。見出しが「いま、ひま！」へ切り替わる | `heavyImpact` 1回 |
| 画面表示 | 飛沫・滲み・下線は静止画。スクロールする一覧に常時アニメーションを載せない | — |
| 長押しで温度感メニュー | 2つの温度感ダブが弧状に、順番をずらして弾みながら出る。ボタン以外の画面は暗くし（ink 35%）、ラベルはダブの下に白地で置く | `mediumImpact` |
| 指が別の温度感に重なる | そのダブが 1.3 倍、他は少し縮む | 変化ごとに `selectionClick` |
| 温度感の上で離す | 選んだダブがボタンへ吸い込まれてから宣言演出 | `heavyImpact` |
| 外して離す／キャンセル | ダブがすぼまって戻る | `lightImpact` |
| ひまを終了 | コーラルの塗りが左から乾いた筆で拭き取られ、下から未宣言の塊が現れる（約700ms）。終わり際で一度止まり、`endHima` が通ったら最後の一拭きで消し切る。**`おわる` を押したときだけ**。失敗したら塗りが戻り、宣言中の見た目はそのまま復元される。期限切れ・サーバー起点の変更ではワイプしない | `lightImpact` |
| チップ選択 | 小さなスケールバウンスとダブの色の切り替え（120〜180ms） | `selectionClick` |
| 「なにする？」シートを開く | ピンクの滲みが**押したコントロールの位置から**飛び出して雫が散り、そのあと5つの塊が1つずつ順番をずらして弾みながら着地する（約620ms） | — |
| タブ切り替え | 新しいタブの飛沫が飛び込み、前の飛沫は縮んで消える（約420ms） | `selectionClick` 1回 |
| マッチカード出現 | スプリングでスライドイン | `mediumImpact`、120ms 空けて `mediumImpact` |
| 友達がひまになる／やめる | カードがフェード＋スライドして並び替わる | — |
| ノック送信 | 紙飛行機がシートの外へ飛んでから閉じる | `lightImpact` |
| 「いいよ！」が届く | 開いているタブの上にオーバーレイで出る（アバターがポンと出て `〇〇から いいよ！`）。小さな紙吹雪が1回だけ（1秒未満）。約3秒またはタップで消え、タップでノック画面を開く。閉じたあとも、その友達の `さそう` は `いいよ！` のまま残る | light → 80ms → light → 80ms → heavy |
| 「あとで」「今回はパス」が届く | 同じオーバーレイ。紙吹雪なし、フェードのみ | `lightImpact` 1回 |
| エラー | 対象のコントロールが横に小さく揺れる | 短い `vibrate`（または `heavyImpact` 1回） |

- 触覚は Flutter 標準の `HapticFeedback` を短い `Future.delayed` で組み合わせる。振動パッケージや音は使わない。
- 効果はすべて1回だけ。常時のキラキラ演出は使わない。
- OSの「アニメーションを減らす」設定に追従する。飛沫の飛び込みは最終状態の静止画に置き換え、タブの飛沫は即座に切り替える（触覚は残してよい）。
- Flutter 標準の `AnimatedSwitcher` / `AnimatedContainer` / `TweenAnimationBuilder` / `AnimationController` / `CustomPainter` を使う。アニメーション用パッケージは追加しない。
- 60fps を保つため、毎フレームでツリー全体を作り直さず、動く部分だけを切り出す。ペイントの形は seed から一度だけ生成してキャッシュし、`RepaintBoundary` で囲む。

### 状態モデル（概念）

```dart
enum HeroPhase { idle, declared, justExpired }

enum Mood { ok, quiet }

enum Activity { game, chat, work, out, any }

class HeroState {
  final HeroPhase phase;
  final Mood mood;
  final Activity? activity; // null = 未選択（表示は「ひま」）
  final int durationMin;    // 30 / 60 / 120
  final DateTime? expiresAt;
}
```

**UIは `HeroState.phase` を単一の正とする。** 見出し・背景・ボタン・残り時間を別々のフラグで管理しない。宣言の成功/失敗・期限切れを含め、状態遷移を1か所にまとめる。

### 実装上の細かい注意

- 画面は `SafeArea` + スクロール可能な本文 + 固定ボトムナビ。
- 横幅基準は360〜430dpを優先。小さめの端末や大きな文字設定で破綻させない。
- グリッドのカード高さは内容で可変になってもよい。名前が長いときは2行または省略で対処。
- 残り時間は `expiresAt` から求め、端末時刻やバックグラウンド復帰に合わせて表示を更新。
- アバターの写真は `ClipOval` 等で丸く表示。アセット未読み込み時のフォールバック必須。
- アイコンは一貫したセットを使用。絵文字はカテゴリを示す用途に絞る。
- `ThemeData` は Material 3 を基礎にしつつ、**見た目はデフォルトのMaterial UIのままにしない**。
- ボタンのタップ可能領域は最低48×48dp。スクリーンリーダー向けに「ゆうさんを誘う」等の意味あるラベルを設定。
- 友達のステータスをネットワークから取得する場合は、ロード中・空・エラーの画面を用意する。

## 8. 画面状態・例外ケース

| 状況 | 表示・動作 |
|---|---|
| アカウント作成直後で友達なし | `まだ友達がいないよ` + `友達を追加` |
| 友達はいるが全員未宣言 | `いまひまな友達は0人` + 空状態イラスト（控えめ） |
| 自分は未宣言 | `いま、ひま？` + `ひまを宣言` |
| 自分は宣言中 | `いま、ひま！` + 残り時間 + `おわる` |
| 宣言の送信失敗 | 状態は変えず `宣言できなかった。もう一度試してね` |
| 残り時間が0になった | 未宣言へ移行。必要なら一時的に終了メッセージ |
| 友達をブロックした | 相互に状態が見えない仕様を優先 |
| オフライン | キャッシュは古い可能性を示し、宣言の成功を偽装しない |

## 9. 優先順位

### P0 — 最初に作る

- ホームの2状態（`いま、ひま？` / `いま、ひま！`）。
- ワンタップの暇宣言・終了・期限切れ。
- 暇な友達の人数とカード一覧。
- 表示名・アバターのフォールバック。
- 友達のみへの公開、基本的なエラー表示。

### P1 — MVPが動いてから

- `なにする？` の任意カテゴリ。
- 宣言時間の変更、`さそう` の共有シート。
- 通知や軽いアニメーション。

### P2 — 後から検討

- Discordとの連携。
- 友達グループ単位の公開範囲。
- ステッカーやリアクションの種類追加。
- デザインテーマ変更。

**非スコープ:** GPS、地図、移動履歴、常時位置追跡、フルチャット機能、投稿フィード。

## 10. デザイン完了・実装受け入れ条件

- [ ] 未宣言時の主見出しが正確に **「いま、ひま？」** である。
- [ ] 宣言中の主見出しが正確に **「いま、ひま！」** である。
- [ ] 宣言中に **「ひまを宣言」** ボタンが表示されない。
- [ ] 宣言中のヒーローが「アバター＋見出し」と「メタ行（`おわる` を含む）」に収まっている（全幅の終了ボタンも、独立した温度感ダブも、`おわる` だけの行もない）。
- [ ] どのコントロールも飛沫の輪郭で切られていない。
- [ ] 「暇を宣言」はカテゴリ選択なしでも1タップで成立する。
- [ ] 残り時間が切れたら自動終了する。
- [ ] 自分の状態と友達の状態が文字で判別できる。
- [ ] 360dp幅でも文字・カード・ボトムナビが重ならない。
- [ ] 200% の文字拡大でもヒーロー・カード・チップが欠けない。
- [ ] ホームとボトムナビに、枠線・区切り線・アウトラインのストロークが残っていない。
- [ ] 形が seed で決まっており、再ビルドやスクロールで変わらない。
- [ ] アニメーション低減時、飛沫は動かず最終状態で描かれる。
- [ ] 未宣言の塊全体が1つのボタン（読み上げ名 `ひまを宣言`）で、長押しの温度感選択がカスタムアクションとして使える。
- [ ] 宣言中の白い見出しとメタ行は、着地中もワイプ中も常にピンクの塗りの上にある。
- [ ] `おわる` が失敗したとき、塗りが一瞬 OFF になってから ON に戻る、というちらつきがない（約700ms のワイプは成功時だけ）。
- [ ] 「なにする？」シートの選択肢はアプリの5つだけで、どれも 48dp 以上・`selected` 付きのボタンとして読み上げられる。
- [ ] テクスチャが無い／読み込み中でも、すべての塗りが平らな色で描かれる（空白や例外にならない）。
- [ ] 文字サイズ拡大、スクリーンリーダー、アニメーション低減を考慮している。
- [ ] 友達の位置情報や距離を要求・表示しない。
- [ ] 「ポップ」だが、必要な操作が一瞬で見つかる。

## 11. 参考デザインとの関係

この仕様書は、会話内で作成した **カラフルな `hima.` ホーム画面モック**を視覚的な出発点とする。

- **残す:** 太い見出し、ピンクのHero、丸い写真アバター、色違いの友達カード、イエローのアクセント、3タブ構成。
- **加える:** 絵の具の飛沫・滲み・雫（3.4）、カテゴリごとの色とアイコン、アバターの温度感バッジ。
- **直す:** 状態とボタン文言の矛盾、宣言中の要素の積み上げ、各カードの視認性、狭い画面への適応、直線と枠線でつながりすぎていたUI要素の分離。ヒーローは「矩形＋ボタン」ではなく**押せる厚い塊**にした。
- **持ち込まない:** whoo/Bumpの地図機能、位置情報共有、固有のブランドデザインやアセット、モックの写真やキャラクター。

> **最終原則:** かわいさは目的ではなく、友達が「暇ならとりあえず開く」体験を支えるための手段。最も目立つのは装飾ではなく、**自分が暇かどうか**と**友達が暇かどうか**。
