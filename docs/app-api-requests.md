# アプリ側で受け持つこと

正本は `docs/api-contract.md`。この文書は、アプリ（`app/`）がサーバーに頼らず自分で組み立てている処理をまとめたもの。サーバーへのお願いはすべて実装済みなので、ここには残っていない。

- **マッチングカード**：`/app/me` の自分の宣言と、`/app/board` の行の mood から、アプリで組み立てる（🌙 は除く）。
- **返答結果の既読**：アプリは `results` を受け取った時点で手元のキューに入れ、`POST /app/knocks/results/seen`（一括）を呼ぶ。キューから1件ずつお祝い表示を出すので、ID ごとに既読にする API は要らない。`GET /app/knocks/sent` は行ごとの既読時刻を返さないため、送信タブの「新着」は `results` で受け取ってから表示するまでの間だけ出す。
- **自動ひま提案**：Android のみ。ネイティブのワーカーが、対象アプリ（既定は X と YouTube）を設定した利用時間（5分／15分／30分／1時間）以上使ったときと、いつものひまな時間に、ローカル通知で「いまひまじゃない？」と提案する。宣言はしない。通知からアプリを開き、温度感を選んだときだけ、アプリが `source=suggested` で `POST /app/sessions` を呼ぶ。設定画面のスイッチが正とするのは端末側の状態（`jp.atsumaro.atsumaro/suggest` の `getState`）で、サーバーの `auto_mode` は互換のために書き込むだけで、誰も読まない。
- **提案の重複を防ぐ設定**：自動ひま提案カードの「Discordでも受け取る」は `/app/me` の `suggest_dm` を表示し、切り替えると `PUT /app/me/settings` で `suggest_dm` だけを部分更新する。オフにするとサーバーの提案（Discord DM と FCM プッシュ）が届かなくなる。自動ひま提案をオンにしたときは同じ提案が二重に届かないよう `suggest_dm` をオフにし、オフに戻したときはオンに戻す（失敗しても端末側のスイッチはそのまま）。自動ひま提案が使えない iOS と no-op ブリッジでは `suggest_dm` を書き換えない。
- **activity を選ばなかったとき**：アプリが `any` として送る。
